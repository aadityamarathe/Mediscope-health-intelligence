# Project Directory Structure

The MediScope repository is organized into clearly defined directories, strictly separating backend logic, frontend presentation, and data management.

## Overall Directory Tree
```text
Mediscopev2/
├── backend/
│   ├── api/
│   ├── crawler/
│   ├── database/
│   ├── nlp/
│   ├── pipeline/
│   └── utils/
├── frontend/
│   ├── public/
│   └── src/
│       ├── components/
│       ├── pages/
│       ├── services/
│       ├── styles/
│       └── utils/
└── README.md
```

## 1. `backend/`
**Purpose**: Contains the entire Python Flask server, data ingestion scripts, NLP processing pipelines, and database connection logic.
**Why it exists**: To isolate the server-side logic from the client-side presentation.
**Major Files**: `app.py` (entry point), `config.py` (environment variables).
**Dependencies**: Connects to MongoDB Atlas, communicates with `frontend/` via REST APIs.

### 1.1 `backend/api/`
**Purpose**: Defines all RESTful HTTP endpoints that the frontend consumes.
**Major Files**: `routes.py`.
**Responsibilities**: Handles incoming requests, queries MongoDB, formats JSON responses, and handles HTTP errors (e.g., 404, 500).

### 1.2 `backend/crawler/`
**Purpose**: Contains the Scrapy framework setup and web scraping spiders.
**Why it exists**: To autonomously ingest raw data from external sources.
**Sub-folder `spiders/`**: Contains `who_spider.py`, `cdc_spider.py`, `who_gho_spider.py`, `disease_api_spider.py`.
**Communication**: Outputs raw data directly into the `raw_articles` MongoDB collection.

### 1.3 `backend/database/`
**Purpose**: Centralizes all MongoDB connection and initialization logic.
**Major Files**: `mongo_connection.py`, `init_db.py`, `seed_diseases.py`.
**Responsibilities**: Maintains a singleton database connection pool and seeds the database with initial disease metadata on first run.

### 1.4 `backend/nlp/`
**Purpose**: The "brain" of the application, containing Machine Learning and Natural Language Processing scripts.
**Major Files**: `ner.py` (Entity Extraction), `relevance.py` (Classification), `train_classifier.py` (Model Training).
**Sub-folder `models/`**: Stores the serialized `.pkl` files (`classifier.pkl`, `vectorizer.pkl`) generated by scikit-learn.
**Dependencies**: Requires `spacy` (`en_core_web_sm`) and `scikit-learn`. Called extensively by the pipeline processor.

### 1.5 `backend/pipeline/`
**Purpose**: Orchestrates the movement of data from raw scraped text to finalized outbreak records.
**Major Files**: `processor.py` (Main loop), `enricher.py` (Case count appending), `scheduler.py` (Cron jobs).
**Communication**: Reads from `backend/crawler/` output in the DB, sends text to `backend/nlp/`, and saves final results back to the DB.

### 1.6 `backend/utils/`
**Purpose**: Contains small, reusable helper functions.
**Major Files**: `severity.py` (Calculates Low/Medium/High severity).

## 2. `frontend/`
**Purpose**: Contains the React 19 Single Page Application (SPA).
**Why it exists**: To provide the interactive user interface and visualize the data processed by the backend.
**Major Files**: `package.json`, `vite.config.js`, `tailwind.config.js`.
**Dependencies**: Node.js, Vite, TailwindCSS.

### 2.1 `frontend/src/`
**Purpose**: The core source code for the React application.
**Major Files**: `main.jsx` (React DOM renderer), `App.jsx` (Root component with React Router).

### 2.2 `frontend/src/pages/`
**Purpose**: Contains the route-level React components (entire screens).
**Major Files**: `Map.jsx`, `Analytics.jsx`, `Compare.jsx`, `DiseaseDetail.jsx`, `Alerts.jsx`.
**Responsibilities**: Fetches data on mount (via `useEffect`) and renders the UI for specific URLs.

### 2.3 `frontend/src/components/`
**Purpose**: Contains small, reusable UI elements.
**Responsibilities**: Used by pages to build the interface (e.g., standard buttons, loading spinners, alert banners).

### 2.4 `frontend/src/services/`
**Purpose**: Abstracts all HTTP communication with the Flask backend.
**Why it exists**: So React components don't have to handle raw `fetch` or `axios` calls directly, keeping components clean.
**Communication**: Sends HTTP GET/POST requests to `backend/api/routes.py`.

### 2.5 `frontend/src/styles/` & `utils/`
**Purpose**: Stores global CSS files (like Tailwind directives) and frontend helper functions (like date formatting or API interceptors).
