1. SYSTEM OVERVIEW
================================================================================

Mediscope is an NLP-powered disease outbreak surveillance dashboard designed for
public health researchers and analysts. The system:

  1. Ingests news articles from WHO and CDC RSS feeds via Scrapy spiders.
  2. Fetches real case-count data from the WHO Global Health Observatory (GHO)
     API and the disease.sh COVID-19 API.
  3. Classifies articles as outbreak-relevant using a TF-IDF / Logistic
     Regression classifier (with keyword fallback).
  4. Extracts disease names and geographic locations using spaCy NER
     (en_core_web_sm), PhraseMatcher, EntityRuler, regex, and substring
     fallback layers.
  5. Enriches extracted outbreaks with case counts from a pre-fetched
     disease_stats collection (sourced from WHO GHO).
  6. Stores all data in MongoDB Atlas (collections: raw_articles,
     processed_articles, diseases, outbreaks, subscribers, disease_stats,
     alerts_log).
  7. Serves processed data through a Flask REST API.
  8. Displays results on a React + Vite frontend with an interactive Leaflet
     map, Chart.js trend visualizations, disease comparison tables, symptom
     search, and email alert subscription.

The system is intended to run on a 6-hour crawl cycle (configurable via the
scheduler module), with the WHO GHO spider running every 24 hours.

4.13  backend/nlp/ner.py  (133 lines)
--------------------------------------------------------------------------------
Purpose: Extracts disease names and geographic locations from text using a
  multi-method approach.

NLP Model: spaCy en_core_web_sm (loaded once at module level)

Disease Extraction Strategy (3 layers):
  Layer 1 — PhraseMatcher:
    - 37 disease keywords added as phrase patterns (attr=LOWER)
    - Matches are normalized via DISEASE_MAP (e.g., "covid" → "covid-19",
      "flu" → "influenza", "hiv" → "hiv/aids")
  Layer 2 — Fallback Substring Scan:
    - Iterates FALLBACK_KEYWORDS against text.lower() using Python "in" operator
    - Catches hyphenated/compound forms that PhraseMatcher misses
      (e.g., "leprosy-free" still matches "leprosy")
    - Same normalization via DISEASE_MAP

Location Extraction:
  - Uses spaCy NER entities with label "GPE" (Geo-Political Entity)
  - Normalizes via LOCATION_MAP (e.g., "U.S." → "United States")

Output Format: {"diseases": list[str], "locations": list[str]}

Note: This module (ner.py) is the one actually imported by processor.py.
  entity_extractor.py is a separate, more sophisticated implementation that
  is NOT currently used by the pipeline.

4.14  backend/nlp/entity_extractor.py  (157 lines)
--------------------------------------------------------------------------------
Purpose: Advanced multi-layer disease and location extraction. Appears to be
  an improved/alternative implementation of ner.py. NOT currently imported by
  any other module in the pipeline.

Extraction Layers:
  Layer 1 — EntityRuler:
    - Adds DISEASE label patterns to spaCy pipeline (before NER)
    - Uses comprehensive DISEASE_ALIASES dict covering 17 diseases with
      multiple aliases each (e.g., tuberculosis: tb, tubercular,
      mycobacterium tuberculosis, consumption, phthisis, etc.)
    - Returns most frequent canonical disease name (via Counter)
  Layer 2 — (skipped in code, goes to Layer 3)
  Layer 3 — Regex Fallback:

      H1N1/H3N2/H5N1)
  Layer 4 — Title Fallback:
    - If article dict provided, re-runs Layer 1 + Layer 3 on title only
    - Catches cases where body text is too generic but title is specific

Output Format: {"diseases": list, "locations": list, "disease": str|None,

4.15  backend/nlp/relevance.py  (113 lines)
--------------------------------------------------------------------------------
Purpose: Determines whether a news article is relevant to disease-outbreak
  surveillance. Provides a dual-strategy approach with graceful fallback.

Strategy 1 — ML Model (when available):
  - Loads classifier.pkl and vectorizer.pkl from nlp/models/ at import time
  - TF-IDF transforms input text
  - Logistic Regression predict_proba → class 1 probability = confidence
  - Threshold: 0.5 (natural decision boundary)
  - Returns {"is_relevant": bool, "confidence": float}

Strategy 2 — Keyword Fallback (when model files absent):
  - Checks text against 18 keywords (diseases, synonyms, symptoms/signals)
  - is_relevant = True if ≥ 1 keyword matches
  - confidence = min(keyword_count / 3, 1.0)

Public API:
  - is_relevant_article(text) → {"is_relevant": bool, "confidence": float}
  - is_model_loaded() → bool

Design Pattern: Strategy pattern with automatic selection at import time.

4.16  backend/nlp/train_classifier.py  (181 lines)
--------------------------------------------------------------------------------
Purpose: Trains the TF-IDF + Logistic Regression classifier used by
  relevance.py. Uses auto-labeling of raw_articles from MongoDB.

Auto-Labeling Heuristic:
  - Positive (1) if text contains ANY disease name (24 diseases) OR ANY
    epidemiological signal word (14 words: outbreak, epidemic, cases, etc.)
  - Uses OR logic (not AND) because small corpus (<300 articles) produced
    too few positives with AND logic

Training Pipeline:
  1. Loads articles from raw_articles (title + description/content)
  2. Auto-labels each combined text
  3. TfidfVectorizer(ngram_range=(1,2), max_features=5000, stop_words="english")
  4. train_test_split(test_size=0.2, stratify=labels, random_state=42)
  5. LogisticRegression(class_weight="balanced", max_iter=1000)
  6. Prints classification_report
  7. Saves classifier.pkl and vectorizer.pkl via joblib

Output: nlp/models/classifier.pkl (~40KB), nlp/models/vectorizer.pkl (~210KB)

4.18  backend/pipeline/processor.py  (618 lines)
--------------------------------------------------------------------------------
Purpose: Main article processing pipeline. This is the core module that
  transforms raw crawled articles into structured outbreak records.

Key Data Structures:
  - GENERIC_DISEASE_TERMS: Set of terms to ignore as disease names (12 terms)
  - COUNTRY_FIX: Dict mapping 36 city/state names to their parent country
  - COUNTRY_ALIASES: Dict mapping 13 country name variants to canonical form
  - COUNTRY_COORDS: Dict of 66 countries with (lat, lng) coordinates
  - DISEASE_NAME_MAPPING: Dict of 8 synonyms → canonical disease names
  - DISEASE_DISPLAY_NAMES: Dict of 28 diseases → display-case names
  - VALID_DISEASES: Set of 12 diseases considered valid for outbreak records
  - CASE_PATTERNS: 3 compiled regex patterns for extracting case counts from
    text (handles "1,300 cases", "5k cases", "millions of deaths")

Key Functions:
  - extract_case_count(text): Regex-based numeric extraction, returns max
    number found
  - calculate_severity(case_count): Simple threshold (>8000=high, >3000=medium,
    else low). NOTE: This is a DIFFERENT severity function from utils/severity.py
    which uses a weighted score of case_count/5000 + occurrences*1.5
  - _normalize_disease_name(disease): Cleans, filters generic terms, maps
    synonyms, falls back to title case
  - _pick_primary_disease(text, candidates, known_diseases): Multi-pass
    matching: NER candidates → disease aliases → known disease names →
    display name keys. Returns earliest match in text (by character index)
  - _pick_primary_country(text, candidates): Multi-pass: NER locations →
    known countries → city/state fix → common locations. Returns earliest match
  - _normalize_country(raw): Maps raw location string to canonical country
    name using COUNTRY_COORDS keys and COUNTRY_ALIASES

process_articles() Main Loop:
  For each article in raw_articles (ALL, not just unprocessed — no
  {processed: False} filter):
    1. Build analysis text from title + content
    2. Extract entities (diseases, locations) via ner.py
    3. Check relevance via relevance.py
    4. Update raw_article with processed=True, is_relevant, etc.
    5. If relevant:
       a. Pick primary disease (multi-pass matching)
       b. Validate against VALID_DISEASES; fallback to text detection
       c. Pick primary country
       d. Extract case count from text
       e. If no case count: enrich from disease_stats via enricher.py
       f. Calculate severity
       g. Upsert to outbreaks (keyed on disease + country + date)
    6. Print statistics summary

IMPORTANT BUG/DESIGN ISSUE: The processor re-processes ALL articles every run
  (no filter on processed=False). This means previously processed articles
  are re-evaluated and either skip as duplicates or get updated in place.

Purpose: Calculates outbreak severity using a weighted score combining
  total case count and number of occurrences (distinct outbreak reports).

7. DATA PIPELINE FLOW (Crawler → NLP → Storage → Serving)
================================================================================

PHASE 1: CRAWLING (crawler/__init__.py → run_all_crawlers())
  1a. WHOHealthSpider crawls WHO RSS → raw_articles (source="WHO")
  1b. CDCHealthSpider crawls CDC RSS → raw_articles (source="CDC")
  1c. DiseaseAPISpider fetches disease.sh → outbreaks (direct, COVID-19 only)
  
PHASE 1B: GHO DATA FETCH (separate, runs every 24h)
  WHOGHOSpider fetches WHO GHO API → disease_stats (7 diseases × many countries)

PHASE 2: PROCESSING (pipeline/processor.py → process_articles())
  For each document in raw_articles:
  2a. Build analysis_text = title + " " + content
  2b. NER Extraction (nlp/ner.py):
      - spaCy PhraseMatcher → disease keywords
      - Substring fallback scan → catches hyphenated forms
      - spaCy NER (GPE label) → locations
      - Normalization via DISEASE_MAP, LOCATION_MAP
  2c. Relevance Classification (nlp/relevance.py):
      - TF-IDF + LogReg model → predict_proba → confidence
      - OR keyword fallback → match count → confidence
  2d. Update raw_article: set processed=True, is_relevant, diseases_found,
      locations_found, confidence
  2e. If NOT relevant → skip
  2f. Disease Resolution:
      - _pick_primary_disease: multi-pass (NER → aliases → known → display names)
      - Validate against VALID_DISEASES (12 diseases)
      - Fallback: _detect_disease_from_text (direct text scan)
      - Guard: if disease name is actually a country name → set to None
  2g. Country Resolution:
      - _pick_primary_country: multi-pass (NER → known → city fix → common)
      - Guard: if country name is actually a disease name → set to None
  2h. Case Count Extraction:
      - Regex extraction from text (comma-separated numbers, "N cases" patterns)
      - Returns max number found
  2i. Case Count Enrichment (if no count extracted):
      - enricher.py → disease_stats lookup (country-specific, then global max)
      - Records source as "who_gho" or "unavailable"
  2j. Severity Calculation:
      - processor.calculate_severity(case_count) [>8000=high, >3000=medium]
  2k. Upsert to outbreaks collection (key: disease + country + date)

PHASE 3: ALERTS (nlp/alerts.py → check_and_send_alerts())
  3a. Fetch all outbreaks (not just recent — see bug note above)
  3b. For each outbreak: find subscribers matching country
  3c. Check alerts_log for duplicates
  3d. Send email (currently simulated) and log to alerts_log

PHASE 4: SERVING (api/routes.py via Flask)
  4a. Frontend calls REST endpoints
  4b. Routes query MongoDB collections directly
  4c. Severity is dynamically recomputed at API time using
      utils/severity.calculate_severity (DIFFERENT formula from processor)
  4d. Data serialized (ObjectId → str, datetime → ISO) and returned as JSON

PHASE 5: DISPLAY (React frontend)
  5a. Axios calls to Flask API
  5b. Data rendered via React components (Map, Charts, Cards, Tables)
